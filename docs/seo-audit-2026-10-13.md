# SEO audit - Ray BodyLab

**Date:** 2026-10-13
**Scope:** `SEO_REQUIREMENTS.md` (committed as f981968). Audit only. Evidence from the repository; one `npm run build` was run for the dist summary.

---

## 1. Summary

The single biggest gate is that `public/robots.txt` blocks every crawler sitewide (`Disallow: /`, public/robots.txt:4), which is deliberate until launch but means nothing else in this report matters to Google until it flips. The most important technical gap is that the homepage HTML shipped to JavaScript-free scrapers carries no `og:image`, `og:url` or canonical tag, so WhatsApp and social previews of the site's most-shared URL fall back to whatever the scraper defaults to. The brief's model of the build is partly outdated: build-time prerendering of per-route meta tags is already implemented (`scripts/prerender-meta.mjs`) and the sitemap regenerates on every build, so option (b) in section 3.1 is done, with gaps rather than a greenfield choice. Both `/` and `/catalog` lack an `h1`, and unknown product/category/brand slugs render indexable soft-404 states with no `noindex`. Everything else is medium or low: thin category/brand pages, an admin placeholder string visible to visitors, random image filenames, and heading-order slips.

## 3. Options for 3.1 (what a crawler receives before JavaScript runs)

**Current state.** Every URL not covered by a prerendered file receives `dist/index.html`: the static defaults from index.html (site title, default description, `twitter:card`), with no product data, no canonical, no `og:url` and no `og:image` (index.html:10-17; verified against built dist/index.html). URLs covered by the prerender step receive a full per-route file: `/catalog`, each category, brand and product gets `<title>`, description, canonical, `og:title/description/url/image` written into `dist/<route>.html` before the CDN serves it (scripts/prerender-meta.mjs:102-121, :138-165; dist listing shows 13 route files). That means WhatsApp and other social scrapers, which do not run JavaScript, see correct per-route meta for all product/category/brand/catalog URLs and generic meta for `/` and `/search`. Google can render the SPA, so runtime `useSeo` values are a backstop rather than the primary path.

**(a) Leave as is and rely on Google rendering JavaScript.**
Effort: none (done). Ongoing cost: none. Covers: Google only; every non-Google scraper keeps seeing the static tags from index.html. Conflicts with the no-SSR rule: no. Verdict: acceptable as a backstop because (b) already exists, but it leaves the homepage gap in finding 2 permanently.

**(b) Build-time prerendering of product/category/brand pages from Supabase data.**
What it is: a post-build script writes one static HTML file per known route from the same catalog query the sitemap uses. Status: already implemented and wired into `npm run build` (package.json build script; scripts/prerender-meta.mjs). Effort to date: done; remaining effort is closing the gaps (homepage file or static tags, optional JSON-LD injection). Ongoing cost: seconds added to each build; data edits need the admin Publish action to trigger a rebuild (src/lib/adminApi.ts:271-276). Conflicts with the no-SSR/no-new-server rule: no, it runs at build time on the existing static host.

**(c) Vercel routing or middleware that serves crawlers a page with the right meta tags.**
What it is: a rewrite or edge function that maps an incoming URL to prebuilt HTML with the right tags. Status in repo: `vercel.json` contains only a catch-all rewrite to `index.html` (vercel.json:2), which serves the generic shell, not per-route meta. Evidence points to Cloudflare Pages as the current host (src/lib/adminApi.ts:271-275, `pages.dev` in the sitemap URL), where the equivalent is serving the `.html` files the prerender step already writes. Effort: re-implements what (b) does, on a second deploy target. Ongoing cost: two deploy configs to maintain. Verdict: not recommended while (b) covers the same ground; only worth revisiting if the hosting decision changes.

**Do not implement any of these in this task** (per section 3.1). Only finding 2's fix (static homepage tags) is recommended, as its own commit in section 5.

## 5. Recommended order of fixes

One commit each, smallest and safest first. None claims a ranking effect; each may help Google or link previewers better understand a page.

1. **Catalog `h1`**: add a visually hidden `h1` on `/catalog` (finding 5). No visual change.
2. **Home `h1`**: add a visually hidden `h1` above the hero carousel (finding 4). No visual change.
3. **Homepage link-preview meta**: add static `og:image`, `og:url` and canonical to `index.html`, or have `prerender-meta.mjs` write dist/index.html (finding 2). Uses the existing default image; no design change.
4. **Soft-404 `noindex`**: pass `robots: 'noindex'` in the not-found branches of Product, Category and Brand (finding 3). Invisible.
5. **Heading order**: `ProductBlock` h5 to h2/h3 (finding 10). No visual change.
6. **JSON-LD baseline**: `Organization`/`WebSite` on `/`, optionally inject route JSON-LD during prerender (finding 11). Invisible markup; same-truthful-data rule applies.
7. **Deploy config**: add `public/_redirects` (or document the Cloudflare SPA setting) and align or retire `vercel.json` (finding 6).
8. **Placeholder text**: stop rendering the admin placeholder on product pages (finding 8), or owner supplies content instead.
9. **Image filenames**: derive storage paths from the product slug (finding 9).
10. **Category/brand intro text**: needs owner approval and a schema migration first (finding 7), then copy is written by the owner.
11. **robots.txt launch swap**: owner-approved launch step with the content listed in finding 1; not part of this task.
